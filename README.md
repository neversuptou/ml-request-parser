# ml-request-parser

Разбор постов с IT-вакансиями из Telegram (аутстафф-каналы) на поля заявки — номер, проект,
позиция, грейд, опыт, срок, рейт, требования, задачи, локация, контакты — локально и бесплатно,
вместо платного разбора DeepSeek.

Полная история, метрики и что пробовали — в [GUIDE.md](GUIDE.md).

## Как работает

Построчная классификация: каждая строка поста -> поле / заголовок / «не поле»,
затем значения собираются из строк.

- `parser/line_model.py` — модель строк: `rubert-tiny2` (дообученная) или быстрая TF-IDF + логрег;
- `parser/line_post.py` — поправки по структуре поста (секции, подзаголовки, чек-листы к резюме);
- `parser/regex_rules.py` — подписанные поля и поля внутри строк (номер, грейд, срок, стаж);
- `parser/extractor.py` — слияние, пометка «⚠️ Проверить вручную» (дайджест, не вакансия, короткий пост), рендер.

Качество (30 заявок, которых модель не видела, сверка с исходным текстом):
**93.0% полей верно** против 95.8% у DeepSeek; в опыте, рейте и контактах модель точнее
(DeepSeek выдумывает ставки и контакты из чужих заявок).

## Запуск

```bash
pip install -r requirements.txt
python cli.py post.txt                  # разобрать пост
uvicorn api.main:app --port 8000        # POST /parse {"text": "..."}
python -m pytest tests -q
```

Модели в репозиторий не входят (`model/`) — обучаются скриптами:

```bash
python scripts/prepare_lines.py                 # выгрузка из БД -> построчная разметка
python scripts/train_lines_baseline.py          # быстрая модель, ~10 мин
python scripts/train_lines_bert.py --base cointegrated/rubert-tiny2 --out model/lines-rubert --lr 1e-4
```

Данные (тексты заявок, резюме) в git не хранятся — там контакты и персональные данные.
